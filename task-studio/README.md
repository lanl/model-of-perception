# Scalar Task Studio

Build illustrated visualization tasks with reference answers computed from the underlying scalar field. Choose datasets, colormaps, operations, selections, aggregations, and actions; exclude individual compatible combinations; sample tasks uniformly; download CSV, Markdown, images, or one complete ZIP.

This folder is a self-contained application. Put its **contents at the root of a new GitHub repository**. It includes the frontend, Python backend, numerical routines, all 12 current datasets, source metadata, tests, and deployment configuration. No files from the research repository or paper are needed. The original research app remains a separate snapshot; future changes to the public app belong here.

## Run locally

Install [uv](https://docs.astral.sh/uv/getting-started/installation/), then run from this folder:

```sh
uv sync --locked
uv run --locked python -m task_app
```

Open http://127.0.0.1:8765. Stop with Ctrl+C. To change the port, append `--port 8766`. To run the production server locally on macOS or Linux:

```sh
bash start.sh
```

Python 3.13.12 is the deployment baseline. The browser interface has no Node/npm build step. Node is only used for an optional visualization test.

## Deploy on Render

1. Push this folder's contents to a new GitHub repository, including `uv.lock`, `render.yaml`, and the data files. Keep the supplied `.gitignore`.
2. In Render, choose **New → Blueprint**, connect that repository, and use the included `render.yaml`.
3. Review the free web-service configuration and deploy. Render generates the session secret and supplies the public hostname and port. Open the resulting `https://…onrender.com` URL.

The [Render Blueprint](https://render.com/docs/infrastructure-as-code) uses these settings:

| Setting | Value |
| --- | --- |
| Runtime | Python |
| Build command | `uv sync --locked --no-dev` |
| Start command | `bash start.sh` |
| Health check | `/healthz` |
| Python | `3.13.12` |
| uv | `0.10.11` |

For a manual **New → Web Service** deployment, use the same commands and environment variables from `render.yaml`. Render provides uv when a `uv.lock` file is present; see [uv configuration](https://render.com/docs/uv-version). If you deploy the enclosing research repository instead, set the service's **Root Directory** to `scalar-task-studio`; the supplied Blueprint and GitHub workflow assume the standalone repository layout.

Render's [free service](https://render.com/docs/free) sleeps after 15 minutes without incoming traffic, takes about a minute to wake, and loses local files on restart, redeployment, or sleep. Visitors should download their bundles promptly. The deployment is a small public demo, with no accounts or persistent storage.

For a custom domain, set `PUBLIC_BASE_URL=https://your-domain.example` and add any additional health-check hostnames to the comma-separated `ALLOWED_HOSTS`. The default Render URL works automatically. This setup uses Render's HTTPS termination; it does not trust arbitrary forwarded host headers.

## Shared demo behavior

Each browser session has its own uploads and can read only its own jobs and downloads. No login is needed. The session cookie is HTTP-only, SameSite=Lax, and Secure on HTTPS; mutations also require a session-specific CSRF token. Uploads are sent to the server, held temporarily in memory, and included in that visitor's generated bundles. They are not added to the public dataset catalog or committed to GitHub.

Generation runs through one shared queue, with one active batch and up to eight waiting batches. Each visitor may have one unfinished batch. The default public limit is 50 tasks per batch. The latest five completed/error batches per session are retained, and downloads expire one hour after completion; sessions expire after one hour of inactivity. Reloading the page retains a live session, but restarting the server clears all sessions and job access. Old files are removed automatically.

Uploaded files are limited to 2.5 MB each, 20 uploads and 20 MB of submitted input per session. The app also caps aggregate uploaded-array/colormap memory and generated-file storage. NPY headers are checked before allocating arrays. Invalid, oversized, or cross-session input is rejected. These limits keep a shared demonstration usable; sustained high traffic needs a separate worker service and shared state store.

| Environment variable | Default | Purpose |
| --- | --- | --- |
| `PORT` | `8765` locally; supplied by Render | HTTP port |
| `SECRET_KEY` | Random on local startup; generated by Blueprint | Signs session cookies |
| `PUBLIC_BASE_URL` | `RENDER_EXTERNAL_URL`, when available | Canonical browser origin |
| `ALLOWED_HOSTS` | Localhost plus public hostname | Additional trusted hostnames |
| `MAX_TASKS` | `50` | Tasks per batch; can be set to `200` |
| `MAX_JOB_SECONDS` | `300` | Cooperative time budget for sampling/rendering |
| `SESSION_TTL_SECONDS` | `3600` | Idle session lifetime |
| `JOB_TTL_SECONDS` | `3600` | Completed-download lifetime |
| `MAX_STORAGE_BYTES` | `536870912` | Generated-file storage budget, checked between tasks and after export |
| `OUTPUT_DIR` | `runs` locally | Dedicated directory for disposable generated files |

The time budget is checked between sampling attempts and tasks; it does not interrupt a single ongoing NumPy or rendering operation. Failed or timed-out batches remove their partial outputs. The queue is in-process: keep **one Gunicorn worker and one service instance**. Four HTTP threads serve the interface while generation runs. `start.sh` removes Render's default Gunicorn `--preload` option so the generation thread starts in the worker, not the master process. Scaling to multiple workers requires moving sessions and jobs to shared storage.

## Files

```text
task_app/               Python application
  static/               HTML, CSS, JavaScript (no build step)
  numerics/             Search, extrema, threshold, correlation routines
  builtin/              Original terrain array/coordinates and two controls

Those metadata are also carried into generated task bundles. No blanket software or data license has been assigned by this packaging step; the source owners should select the software license before advertising open-source reuse.

## Tests and optional dataset downloads

```sh
uv sync --locked --extra datasets
uv run --locked --extra datasets python -m unittest discover -s tests -v
node tests/test_visualization.mjs
```

Prepared arrays are bundled, so deployment does not download upstream scientific data. To re-fetch selected sources:

```sh
uv run --locked --extra datasets python -m task_app.dataset_download --only mitosis retinal_lesions
```

This optional command requires network access and preserves bounded source-download behavior. Restart the app after changing prepared datasets. No database, external model API, or secret API key is required.

To make a fresh source ZIP without virtual environments, uploads, caches, or generated batches:

```sh
uv run --locked python scripts/package_release.py
```

The archive is written to `dist/scalar-task-studio-github.zip` with the repository files at its root.
